## 2. Data

No external data. Every sample is generated by simulating the system of the paper (Eqs. 9–10) with the
parameters of Secs. 4.1–4.3. All randomness comes from NumPy `default_rng` with fixed seeds
(seed 0 for T1–T6, seeds 1–20 for T7), so every run gives the same numbers.

## 3. Run order

```bash
python main.py            # everything: about 3.5 h on 2 CPU cores (the 20 Monte Carlo runs take most of it)
python main.py --quick    # 1-2 minute smoke test (20 iterations, 2 Monte Carlo runs) -> results_quick/
```

To save time, the Monte Carlo can be split over several terminals (one per CPU core), e.g.
`python run_sec46.py 1 5`, `python run_sec46.py 6 10`, ...: finished seeds are skipped on re-runs.
On an 8-core laptop the 20 runs take about 20–30 minutes this way.

`main.py` runs, in this order:

| Step | Script | Produces | Target |
|---|---|---|---|
| 1 | `diagnostics.py` | checks D1–D8, `fig_diagnostics.png`, `diagnostics.json` | verification |
| 2 | `run_sec44.py` | seed-0 optimization, `sec44.json`, `sec44.npz` | T1, T2 |
| 3 | `run_adam.py` | Adam cross-check on seed 0, `adam.json` | optimizer check |
| 4 | `run_early.py` | H1 test: the same run stopped after 16/20/25 iterations, `early.json` | T2 analysis |
| 5 | `run_sec45.py` | Schroeder signal, `sec45.json` | T6 |
| 6 | `validation.py` | ε sensitivity, 30³ grid, other x0, P = 12 → `validation.json` | verification |
| 7 | `run_sec46.py` | 20 Monte Carlo runs (≤1000 iterations each), `mc/seed_XX.json` | T7 |
| 8 | `make_figures.py` | all figures, `comparison_table.csv`, `numbers.tex` | T1–T7 |

Steps 3–8 need the output of step 2. `results/numbers.tex` holds every number used in the M3 report.

## 6. Documented choices and deviations

* Dynamics as **Eq. (9)**: 1/m multiplies only the velocity equation (Eq. 11 is a notation error).
* ε = 1e-3, 20³ grid with `linspace`, steady state from P = 8 periods with an explicit check: not stated in the paper.
  P was raised from the M2 value 5 to 8 because the first optimized signal failed the check at P = 5 (see `results/old_P5/`).
* Optimizer: SciPy L-BFGS-B (the paper used MATLAB `fmincon`, options not reported).
* Gradient: hand-derived reverse-mode (adjoint) gradient instead of PyTorch autograd, verified against finite differences (D6).
